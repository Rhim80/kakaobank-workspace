# update-workspace

디스코드 `워크스페이스-업데이트` 채널에 올라온 압축파일로 내 워크스페이스를 업데이트하는 스킬.

압축을 그냥 푸는 것과 다른 점은 셋이다.

- **내가 고친 파일은 안 덮는다.** 덮을지 말지 나에게 물어본다.
- **내가 만든 스킬은 건드리지 않는다.**
- **아무것도 지우지 않는다.** 원본에서 빠진 스킬이 있으면 알려만 주고, 지울지는 내가 정한다.

이게 되는 이유는 압축파일 안에 `.dbt-version.json`이 같이 오기 때문이다. 지난번에 받은 게 뭐였는지가 거기 적혀 있어서, 지난번 것 · 지금 내 파일 · 이번에 받은 것 셋을 비교할 수 있다.

## 하는 일

### 1. 워크스페이스가 어디인지 정한다

지금 열린 폴더가 워크스페이스면 그대로 쓰고, 아니면 **묻는다.** 멈추지 않는다 — 사람마다 클로드 코드를 켜는 폴더가 다르다.

```bash
ROOT=""
test -f CLAUDE.md && test -d .claude && ROOT="$PWD"
echo "${ROOT:-(여기가 아님)}"
```

비어 있으면 사용자에게 **"워크스페이스 폴더가 어디예요?"**라고 묻고, 받은 경로를 확인한 뒤 쓴다.

```bash
R="<사용자가 준 경로>"
test -f "$R/CLAUDE.md" && test -d "$R/.claude" \
  || echo "ERROR: 워크스페이스가 아닙니다 ($R 에 CLAUDE.md·.claude 없음)"
```

아래 명령에는 이 경로를 `--root "$ROOT"`로 넘긴다. 지금 열린 폴더가 워크스페이스면 안 줘도 된다(기본값이 현재 폴더다).

**워크스페이스 폴더를 안 열고 켰으면 파일을 쓸 때 권한을 물어볼 수 있다.** 그때는 승인하면 된다고 알려준다.

### 2. 압축파일 찾기

사용자가 경로를 줬으면 그걸 쓴다. 안 줬으면 내려받기 폴더에서 찾아 보여주고 고르게 한다.

```bash
ls -t ~/Downloads/*.zip 2>/dev/null | head -5
```

여러 개면 사용자에게 어느 것인지 묻는다. 고르지 말고 묻는다.

### 3. 파이썬 이름 찾기

```bash
PY=""
for c in python3 python py; do
  v=$("$c" --version 2>&1) || continue
  case "$v" in Python\ 3.*) PY="$c"; break ;; esac
done
[ -z "$PY" ] && echo "ERROR: 파이썬 3이 없습니다. setup-workspace 스킬의 4단을 먼저 하세요."
```

이름을 고정하지 않는 이유는 `setup-workspace`와 같다 — 윈도우에는 `python3`라는 이름의 가짜가 깔려 있다. 이 스크립트는 표준 라이브러리만 쓰므로 venv 활성화는 필요 없다.

### 4. 무엇이 바뀌는지 먼저 본다

스크립트 위치는 **설치한 곳에 따라 다르다.** 워크스페이스에 넣은 사람도, `~/.claude/skills`(글로벌)에 넣은 사람도 있다. 고정하지 말고 찾는다.

```bash
S=""
for c in "$ROOT/.claude/skills/update-workspace/scripts/update_workspace.py" \
         ".claude/skills/update-workspace/scripts/update_workspace.py" \
         "$HOME/.claude/skills/update-workspace/scripts/update_workspace.py"; do
  [ -f "$c" ] && { S="$c"; break; }
done
[ -z "$S" ] && echo "ERROR: update_workspace.py를 못 찾았습니다"
```

```bash
"$PY" "$S" plan <압축파일 경로> --root "$ROOT"
```

파일은 하나도 안 건드린다. JSON이 나온다. 갈래는 여덟이다.

- `add` — 이번에만 있다. 새로 생긴 것
- `update` — 원본이 바뀌었고 내 파일은 그대로. 갱신
- `same` — 내용이 같다. 할 일 없음
- `yours_modified` — 원본은 그대로인데 내가 고쳤다. 안 건드림
- `conflict` — 원본도 바뀌고 나도 고쳤다. **물어봐야 함**
- `unknown` — 지난번 기록이 없어 누가 고쳤는지 모른다. **물어봐야 함**
- `gone` — 원본 킷에서 빠졌다. **지우지 않는다.** 알려만 준다
- `yours` — 내가 만든 것. 안 건드림

이걸 그대로 보여주지 말고 사람 말로 옮겨 적는다. **맨 먼저 `root`가 어느 폴더인지 말한다** — 업데이트할 폴더를 잘못 잡았으면 여기서만 알아챌 수 있다. 스킬 이름 단위로 묶어서 몇 개 생기고 몇 개 갱신되는지, 그리고 **물어봐야 하는 것만 파일별로** 적는다. `same`·`yours`는 개수만.

물어봐야 하는 게 있으면 하나씩 묻는다. 한꺼번에 묻지 않는다.

- `conflict`·`unknown` → "새 것으로 바꿀까요, 내 것을 둘까요?" 필요하면 두 내용을 보여준다

`gone`은 묻지 않는다. **"이 스킬은 원본 킷에서 빠졌습니다. 그대로 두었으니 계속 쓰셔도 되고, 안 쓰시면 지워드릴게요"**라고 알리고 넘어간다. 지워달라고 하면 그때 `--drop`을 준다.

### 5. 승인받고 적용한다

```bash
"$PY" "$S" apply <압축파일 경로> --root "$ROOT" \
  --take skills/어디/SKILL.md \
  --drop skills/저기/SKILL.md
```

- `--take` — 물어본 것 중 **새 것으로 바꾸기로 한** 경로 (여러 번 쓸 수 있다)
- `--drop` — 참가자가 **지워달라고 한** 경로. 안 주면 아무것도 안 지운다
- 아무것도 안 주면 `add`·`update`만 하고 나머지는 그대로 둔다

덮어쓰거나 지우는 파일은 먼저 `.claude/.dbt-backup/<시각>/`에 복사된다. 잘못 눌러도 되찾을 수 있다.

### 6. 끝나고 알린다

- 무엇이 생기고 바뀌고 없어졌는지 한 줄씩
- 백업이 있으면 그 경로
- **새 스킬은 잠깐 뒤 저절로 잡힌다** — 클로드 코드가 스킬 폴더의 파일 변화를 지켜보고 있어서 재시작이 필요 없다. 방금 받은 스킬을 곧바로 부르면 아직 없다고 나올 수 있으니, 그때만 한 번 새로 열면 된다. **예외는 `skills` 폴더 자체가 새로 생긴 경우** — 세션이 시작할 때 없던 폴더는 지켜보지 않으므로 그때는 새로 열어야 한다 (글로벌 `~/.claude/skills`에 처음 넣는 사람이 여기 해당한다)

## 처음 받는 사람

`.dbt-version.json`이 아직 없으면 지난번 기록이 없다. 그러면 내용이 다른 파일이 누가 고친 건지 알 수 없어서 전부 `unknown`으로 나온다.

이때는 **`same`이 아닌 것을 하나씩 물어야 한다.** 개수가 많으면 "대부분 캠프 때 받은 그대로일 텐데, 고쳐 쓰신 스킬이 있나요?"를 먼저 묻고 그 답에 따라 나머지를 한꺼번에 처리해도 된다. 한 번 적용하고 나면 다음부터는 안 물어본다.

원본에서 빠진 파일은 첫 회에 못 찾는다. 비교할 기준이 없기 때문이다. 그것도 알린다.

## 스킬 하나짜리 압축파일을 받았다면

이 스킬 자체를 배포할 때 쓰는 작은 압축파일에는 `.dbt-version.json`이 없다. 그건 이 스킬이 아니라 그냥 풀어서 `.claude/skills`에 넣으면 된다. 스크립트가 그 경우를 알아보고 그렇게 안내한다.

## 원칙

- **덮기 전에 묻는다.** 물어야 하는 것을 묻지 않고 넘어가면 참가자가 고쳐 쓰던 스킬이 사라진다
- **먼저 지우지 않는다.** 원본에서 빠졌다는 건 만든 사람이 안 쓴다는 뜻이지, 이 워크스페이스 주인이 안 쓴다는 뜻이 아니다. 고치지 않고 그대로 잘 쓰는 게 오히려 정상이라, "안 고쳤으니 안 쓰겠지"로 지우면 잘 쓰던 도구가 말없이 사라진다 (이림 2026-08-19)
- **하나씩 묻는다.** 목록으로 한꺼번에 던지면 그냥 예를 누른다
- **비교와 계산은 스크립트가 한다.** 파일 내용을 눈으로 비교해 판정하지 말 것 — 검사값으로 갈린 결과를 옮겨 적기만 한다
- **`add`·`update`는 자동.** 여기까지 묻기 시작하면 매번 스무 번을 눌러야 해서 아무도 업데이트를 안 한다
- **반복 안전.** 같은 압축파일을 두 번 적용해도 두 번째는 할 일이 없다고 나온다
- **`settings.local.json`은 비교에서 빠진다.** 내 기계 설정이라 원본에 없다
- **받는 사람의 상황이 다 같다고 보지 않는다** (이림 2026-08-19). 스킬을 워크스페이스에 둔 사람도 글로벌에 둔 사람도 있고, 클로드 코드를 켜는 폴더도 제각각이다. **경로를 고정하면 그 사람만 막힌다** — 못 찾으면 멈추지 말고 묻는다

## 이 뒤에 어떻게 되나

한 번 적용하면 `.claude/.dbt-version.json`이 이번 것으로 바뀐다. 그게 다음 비교의 기준이 된다.

물어본 것을 "내 것 두기"로 정했으면, 그 파일은 앞으로 내 것으로 남는다. 원본이 그 파일을 **또** 고치는 날 다시 물어본다. 원본이 안 건드리는 동안은 조용하다.
