# test-report — 테스트 결과를 파일 하나로

워크스페이스를 만든 사람(이림)은 이 PC를 볼 수 없다. 사내 PC에서 무엇이 되고 무엇이 막히는지는 여기서 만든 파일이 유일한 창이다. 그래서 이 파일은 **있는 그대로**여야 한다 — 잘 됐다고 다듬지 않고, 에러는 원문으로 넣는다.

**먼저 탐색하지 않는다.** 이 PC에는 이 워크스페이스 폴더 하나뿐인 것으로 본다 — 상위 폴더나 다른 폴더를 뒤져 "테스트가 여러 개 있다"고 되묻지 않는다(1번 명령이 현재 폴더만 본다). 부르면 바로 1번 명령을 돌린다.

## 1. 기계가 찍는 부분

```bash
test -f CLAUDE.md && test -d 00-inbox || echo "워크스페이스 루트에서 실행하세요"
mkdir -p 00-system/wiring
bash .claude/skills/test-report/scripts/collect_env.sh > 00-system/wiring/테스트-보고.md 2>&1
```

스크립트는 환경(OS·Claude Code 버전·node·python·gws 등) · `claude mcp list` 원문 · 바깥 접근(anthropic·npm·pypi·github 응답 코드) · 스킬 목록 · 배선도 진행 상태를 찍는다. 판단은 안 한다.

## 2. 사람에게 묻는 부분

파일 끝에 아래 절을 붙인다. 두 가지를 묻고 **답한 말 그대로** 적는다. 답이 없으면 "(없음)". 에러 메시지가 있었으면 다듬지 말고 원문을 붙여 달라고 부탁한다.

```markdown
## 돌려본 것
- <무엇을 시켰나> → <어떻게 됐나>

## 막힌 것 (에러 원문)
- <무엇을 시켰나> → <에러 메시지 그대로>

## 그 밖에 이림에게 전할 말
- (없음)
```

묻는 말: "오늘 이 워크스페이스에서 무엇을 시켜 보셨나요? 된 것과 안 된 것을 말해 주세요. 에러가 났으면 그 메시지를 그대로 붙여 주세요." 한 번에 다 묻고, 나온 대로 적는다. **없는 말을 보태지 않는다** — 참가자가 "코코"라고 하면 "코코"로 적는다, 그게 무엇인지 괄호로 풀거나 워크스페이스의 다른 이름과 이어 붙이지 않는다. 이림이 그 원문을 보고 판단한다.

## 3. 끝

`00-system/wiring/테스트-보고.md` 경로를 알려주고, 이 파일을 이림에게 메일 회신에 첨부해 달라고 말한다. 다른 곳으로 보내지 않는다 — 이 스킬은 파일을 만들기만 한다.
