# ripple

파일 변경이 참조·진행 기록·하루 기록에 미치는 영향을 찾는다.

워크스페이스 루트의 `00-system/선언-표면.yaml`이 경로·형식의 원본이다. 아래 래퍼가 실행 가능한 Python 3.9 이상을 확인한다. YAML 모듈은 킷에 동봉되어 있어 패키지 설치는 없다. 선언 오류·실행 실패를 빈 목록으로 숨기지 않는다.

## 1. 변경과 선언 확인

이번 세션의 실제 변경 파일을 정리한다. 세션 맥락이 없으면 git status/diff와 사용자 지정 범위로 확인한다. 기억에 없는 파일을 수정했다고 가정하지 않는다.

```bash
bash .claude/scripts/surfaces.sh resolve
bash .claude/scripts/surfaces.sh progress '변경한 파일의 상대 경로'
```

진행 탐색은 선언의 `진행.루트` 아래 상위 폴더의 기록 파일과 배선도 `줄기[].기록`을 함께 찾는다. 여러 개면 관계를 읽어 필요한 것만 고른다. 없는 파일은 생성할 후보로 보고하며 임의 위치를 선택하지 않는다.

## 2. 영향 찾기

- 직접 참조: 파일명·옛 경로·스킬명·변경한 규칙을 워크스페이스에서 검색한다. Markdown 외 YAML·스크립트도 포함하며 숨김 `.claude`도 검색한다.
- 스킬/에이전트 추가·변경이면 해당 README 카탈로그와 호출하는 스킬을 읽는다.
- 진행 기록: 위 탐색 결과를 읽고 이번 사실이 타임라인/다음 액션에 이미 반영됐는지 본다. `morning`의 wiring 표식과 같은 내용을 다시 추가하지 않는다.
- 오늘 노트: resolve의 `하루파일`이 이미 있을 때만 `하루.완료섹션`의 누락을 찾는다. 없으면 만들지 않는다.
- 절차 변경이면 새 규칙과 충돌하는 옛 단계를 찾아 함께 수정 후보에 넣는다.

검색에서 .git·가상환경·node_modules·보관 폴더는 제외한다. 배선도의 원본함 파일은 근거로 읽을 수 있지만 고치거나 옮기지 않는다. 실행상태·승인 제안을 일반 관련 문서처럼 바꾸지 않는다.

## 3. 반영

필요한 변경만 파일·이유·조치로 제시한다. 이미 사용자가 승인한 수정 범위는 진행하고, 새 범위는 선택받는다. 파일을 읽고 최소한으로 수정한다.

진행 파일 신규 생성이 승인되면 `진행.템플릿`을 읽는다. 템플릿이 없으면 오류로 알리고 임의 대체 양식을 만들지 않는다. 업무 루트에 선언된 파일명으로 만들고, 배선도 줄기의 기록 경로가 바뀌면 선언도 맞춘다. 기존 기록은 재생성하지 않는다.

완료 후 바꾼 파일과 남은 항목을 보고한다. `위키.위치/index.md`를 읽고 재사용할 지식이 있으면 wiki-ingest를 제안한다. 위키 반영은 그 스킬이 맡는다.
