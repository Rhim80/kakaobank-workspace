# morning — 선언을 읽고 하루를 시작한다

Claude Code의 Skill 도구로 수집·병목·todo·daily-note를 호출한다. 자동 예약 실행은 이 스킬의 범위가 아니다.

## 0. 준비와 재개

먼저 `../wiring/references/declaration.md`를 읽는다(워크스페이스 기준 `.claude/skills/wiring/references/declaration.md`). 스크립트는 래퍼로 부른다(파이썬 이름을 직접 쓰지 않는다).

```bash
bash .claude/skills/wiring/scripts/wiring.sh validate --ready
bash .claude/skills/wiring/scripts/wiring.sh queue
```

validate 결과의 `미등록원문`·`원본없음`이 비어 있지 않으면 본인에게 보여준다(미등록은 1에서 intake가 등록하고, 원본없음은 버림으로 닫을지 묻는다).

오류면 멈추고 wiring에서 고칠 자리를 안내한다. 마크다운 배선도만 있으면 YAML 이관부터 한다. `선언.yaml`과 `실행상태.yaml`을 읽는다. queue의 승인대기·승인됨은 새 자료가 없어도 이번에 이어갈 일이다.

`bash .claude/scripts/surfaces.sh resolve`로 공통 표면 선언도 검사한다. 실패하면 먼저 해당 선언·템플릿을 바로잡는다.

## 1. 모은다

선언의 `수집스킬`을 Skill 도구로 호출한다. 통로마다 실행상태의 이어받기부터 조회하고 store로 등록한 뒤 result를 남기는지 확인한다. 실패한 통로는 마지막 성공 지점을 유지하며 실패 이유를 보여준다. 직접 넣기 통로는 수집 스킬이 `wiring.sh intake <통로id>`로 등록한다 — 끝난 뒤 validate의 `미등록원문`이 비었는지 본다.

수집 결과는 성공 N건·성공 0건·실패를 구분한다. 실패를 0건으로 숨기지 않는다. 이번 수집 건수와 이전부터 남은 승인대기 건수는 따로 보고한다.

## 2. 처리와 제안

queue를 다시 실행한다. `상태: 신규`이고 `병목대상: true`인 자료가 있고 `병목.실행: 아침`이면 그 자료 id들을 공백으로 이어 인자로 `병목.스킬`을 Skill 도구로 호출한다(연결 규약은 reference 「병목 스킬과 morning의 연결」). 병목 스킬은 제안 파일만 만들고 status는 morning이 부른다. 실패하면 해당 자료를 신규로 유지하고 알린다. `직접`이면 자동 호출하지 않고 이번에 실행할지 묻는다. 병목 처리가 필요한 자료를 일반 기록으로 바꿔 완료하지 않는다.

건별 제안은 `00-system/wiring/제안/<자료id>.md`에 만든다. 원문은 변경하지 않는다. 줄기·반영할 내용·성격(기록/할 일/일정/알아둘 것/버림)·원문 근거·반영 위치를 적는다. 한 원문에 여러 일이면 항목을 나눈다. 섞임 통로에서 줄기를 못 정하면 불명으로 본인에게 묻고 선언 수정 후보로 올린다.

제안 파일을 만든 뒤 status로 승인대기를 기록한다. 기존 승인대기는 새 제안을 만들지 않고 원래 제안을 보여준다. 새 자료가 없어도 이 목록을 건너뛰지 않는다. 사용자가 수정하면 제안에 반영한 최종 내용을 확인받는다.

## 3. 확정된 것만 둔다

사용자가 승인한 정확한 항목과 답을 제안 파일에 남기고 status로 승인됨을 기록한다. 일부만 승인한 자료는 승인대기로 유지하고, 승인된 항목만 처리한다. 나머지 항목까지 확정되기 전에 자료 전체를 승인됨으로 바꾸지 않는다.

반영 전에 reference의 `wiring:자료id:항목번호` 표식을 대상 파일에서 확인한다. 이미 반영한 것은 중복 추가하지 않는다. 이전에 승인됨으로 멈춘 자료도 같은 방식으로 이어간다.

- 기록: 선언의 줄기 기록 파일 타임라인/로그에 원본 경로와 함께 적는다.
- 할 일: `todo`를 Skill로 호출하고 원문 경로와 `--key wiring:자료id:항목번호`를 전달한다. 완료 보관에도 같은 표식이 있을 수 있으므로 `todo`의 기존/완료 응답을 반영 근거로 확인한다. active-todos를 임의로 직접 수정하지 않는다. 날짜·기한이 있으면 캘린더에 넣을지 별도로 묻는다.
- 일정: 캘린더 쓰기를 별도로 승인받고, 가능한 도구로 실행한 결과를 조회한다. 도구가 없으면 daily note에 남긴다. 외부 쓰기 결과가 불명이면 재전송하지 않는다.
- 알아둘 것: 줄기 기록 파일 메모에 남긴다. 반복되는 지식이면 wiki-ingest를 제안하고 승인받아 호출한다.
- 버림: 사용자가 확정한 뒤 status로 버림을 기록한다. 원본은 보존한다.

승인 항목의 반영 위치와 표식을 확인한 뒤에만 반영완료를 기록한다. 기록 파일을 바꿨으면 ripple을 호출한다. 제안과 상태를 써 둔 것만으로 실제 반영이 완료됐다고 하지 않는다.

## 4. 하루 기록

daily-note를 Skill로 호출한다. 승인을 기다리며 턴을 끝낼 때도 여기까지는 한다 — 답이 안 오면 노트가 안 남는다. 오늘 수집·반영·남은 승인대기·실패 통로를 실제 실행 결과에서 집계해 남긴다. 병목 스킬을 직접 실행하기로 했다면 남은 일로 알려준다. 원문이나 회사 시스템을 임의로 수정·발신하지 않는다.
