# wiring — 내 배선도를 그리고 깐다

배선도는 "내 정보가 도는 길"의 그림이다. 이 워크스페이스에서 길은 **일 줄기별로** 따로 온다 — 개발 문의는 메신저 채널로, 실적은 시트로, 기획 변경은 회의로. 그래서 배선도의 단위는 단계가 아니라 **줄기**다. 줄기 하나가 배선 하나다.

흐름은 넷이다. **모은다**(줄기별로 원본함에) → **제안한다**(어디에 무엇을 반영할지, 섞이는 통로면 어느 줄기인지) → **승인**(본인) → **둔다**(내 AI가 다음에 알 수 있게 워크스페이스 md에). 회사 시스템(위키·메신저·Jira)에 쓰는 것은 그 밖의 일이고 본인이 한다.

세 가지가 이 스킬의 성격을 정한다.

- **Claude는 지어내지 않고 되읽는다.** 줄기 표의 첫 판은 본인이 사전 업무파악에 쓴 말에서 만든다. 응답에 없는 것을 채우지 않는다. 확정은 매 칸 본인 몫.
- **묻지 말고 대본다.** "빠진 게 있나요"는 답이 안 나온다. 이 PC에 연결된 시스템 목록과 거기서 실제로 가져온 한 건을 보여주고 "이건 어느 줄기예요"로 묻는다.
- **첫날 한 바퀴, 그다음은 계속 고친다.** 배선은 한 번에 완성되지 않는다. 직접 넣기로 둔 길은 나중에 바꿀 후보로 표시해 둔다.

원본 파일은 `00-system/wiring/배선도.md` 하나다. 진행 상태도 이 파일 머리말의 `진행:` 줄이 원본이다 — 같은 상태를 다른 곳에 적지 않는다.

## 시작 — 어디까지 됐나

```bash
test -f CLAUDE.md && test -d 00-inbox || echo "워크스페이스 루트에서 실행하세요"
test -f 00-system/wiring/배선도.md && sed -n 1,6p 00-system/wiring/배선도.md || echo "배선도 없음 — 1단계부터"
```

`진행:` 줄의 빈 체크 중 첫 것이 이번 단계다. 한 세션에 한 단계만 끝내도 된다. 단계를 넘어갈 때는 매번 "여기까지 맞습니까"를 묻고 답을 들은 뒤에 간다. 앞 단계의 확정 답을 다음 단계 시작의 허락으로 읽지 않는다 — 파일을 쓴 뒤 멈추고 "2단계로 갈까요"를 따로 묻는다.

## 1단계 — 줄기 표

목적: 내 일이 몇 줄기이고, 줄기마다 무엇이 어디서 들어와 내가 무엇을 하고 어디로 나가는지를 본인 말로 표에 놓는다. 질문과 예는 `references/streams.md` — **그 파일을 읽고 진행한다.**

1. 사전 업무파악 응답을 받는다. "사전 업무파악에 적으신 내용을 그대로 붙여 주세요" — 없으면 응답 문항(핵심업무 · 주간흐름 · 사용도구 · 소통방식) 순서로 말로 받는다.
2. 응답에서 줄기 표를 만든다. 열은 넷 — **줄기 · 들어오는 곳 · 내가 하는 것 · 나가는 곳**. 칸의 말은 응답 문장에서 그대로 가져온다. 응답에 없는 칸은 비운다 — 채우지 않는다. **희망도구·자유메모의 문장은 표에 넣지 않는다** — 그건 바람이지 지금 도는 흐름이 아니다(19명 테스트에서 옥지혜 "구글 시트로 초안을 받아 … 희망"이 나가는 곳에 들어갔다). 3단계 병목 재료로만 쓴다.
3. 표를 보여주고 "맞나요"를 묻는다. 줄기가 갈리거나 합쳐지고 이름이 바뀐다. 본인이 고친 말로 바꾼다. **답을 듣기 전에는 파일을 만들지 않는다** — 첫 판은 화면에만 보이고, 배선도.md는 본인이 "맞다"고 한 표로 처음 생긴다(19명 테스트에서 3명분이 묻기 전에 파일부터 썼다).
4. 표를 `assets/wiring-template.md`를 복사한 `00-system/wiring/배선도.md`의 1절에 적는다. 머리말 `줄기 [x]`.

**섞이는 통로 표시** — 같은 "들어오는 곳"이 두 줄기 이상에 있거나 외부 접점(메일·카톡·고객 메신저)이면 그 통로는 여러 줄기가 섞여 온다. 1절 표에서 그 통로에 `(섞임)`을 붙인다. 뒤에서 제안할 때 이 통로의 건만 "어느 줄기인가"를 가른다. 사내 메신저 채널 하나가 한 줄기에만 있으면 붙이지 않는다.

## 2단계 — 길 확인 · 실제로 한 건

목적: 줄기 표의 "들어오는 곳"마다 이 PC에서 자료가 실제로 들어오는지를 **가져온 파일**로 확인한다. 연결됐다는 한 줄은 근거가 아니다. 판정법은 `references/lanes.md`.

```bash
bash .claude/skills/wiring/scripts/check_lanes.sh
```

1. 출력을 본인과 같이 읽는다. 연결된 시스템 중 **줄기 표에 없는 것**이 있으면 "이것도 일에 쓰나요, 어느 줄기예요"를 묻는다 — 줄기가 늘거나 "안 쓴다"로 닫힌다. 「이 폴더에서는 안 켜지는 MCP」 절에 이름이 있으면 이 폴더에서 다시 등록할지 본인이 정한다.
2. 들어오는 곳마다 길을 하나 붙인다 — MCP / CLI / 직접 넣기. **길은 이 셋뿐이다.** 공개 웹사이트(타행 사이트·협회 통계 페이지)는 오늘은 직접 넣기로 적고 "나중에 바꿀 후보"에 둔다 — 2단계에서 브라우저 자동화·스크래핑을 만들지 않는다(박혜주 테스트에서 협회 사이트를 20턴 넘게 뒤지다 세션이 끊겼다). 그것이 병목이면 3단계의 스킬 후보다. 한 길의 확인은 호출 세 번 안에 끝난다 — 안 되면 그 자리에서 직접 넣기로 적는다.
3. **MCP·CLI 길은 그 자리에서 한 건 가져온다.** MCP면 그 서버의 도구 목록을 보고 읽기 도구를 골라 "어제 이후" 또는 "최근 것 하나"로 부른다. CLI(gws)면 명령을 찾아 돌린다(`gws --help`, 시트·드라이브·메일). 가져온 것을 아래 원본함 규약대로 `00-inbox/raw/<들어오는 곳>/`에 파일로 떨어뜨리고 본인에게 보여준다 — "이런 게 들어오는데 어느 줄기예요." 줄기가 없으면 표에 줄이 하나 는다.
4. 된 호출을 2절 선언표에 적는다 — 시스템 · 길 · 무엇을(채널·탭·라벨) · 언제부터 · 된 호출(도구 이름과 인자, 또는 명령 한 줄) · 근거(떨어진 파일 경로). **된 호출은 그대로 붙인다** — 다음에 수집 스킬이 이 줄을 읽고 같은 호출을 반복한다. **`<시트ID>`·`<탭>` 같은 자리표시자를 쓰지 않는다** — 대역으로 확인했어도 실제로 돌린 값 그대로 적고, 바꿀 값은 "나중에 바꿀 후보" 칸에 적는다(박혜주 테스트에서 자리표시자를 적어 다음 날 `morning`의 수집이 404로 멈췄다). 읽기 도구가 없거나 안 되면 그 시스템은 오늘 직접 넣기로 적고 "나중에 바꿀 후보"에 표시한다.
5. 직접 넣기 길(회의·Figma·Jira 등)은 선언표에 "직접 넣기 · 본인이 `00-inbox/raw/<길>/`에 넣음"으로 적고, 나중에 바꿀 후보 칸에 무엇이 되면 바뀔지 한 줄.

머리말 `길확인 [x]`.

**원본함 규약** (길이 무엇이든 같다 — 뒤 단계가 어느 길에서 왔는지 신경 안 쓰게)
- 경로: `00-inbox/raw/<들어오는 곳>/<YYYY-MM-DD>_<제목 또는 id>.md`
- 머리말 세 줄: `출처:` (시스템·채널) · `가져온 때:` · `줄기:` (비움 — 제안이 채운다)
- 본문: 원문 그대로. 고치지 않는다. 제안은 본문 아래 `## 제안` 절에만 붙인다.
- 상태: `00-system/wiring/수집-상태.md`에 들어오는 곳마다 한 줄 — 마지막 수집 때 · 건수 · 결과(`N건` / `0건` / `안 돌았다: <에러 원문>`). 0건과 안 돌았다를 가른다.

## 3단계 — 병목 줄 고르기

목적: 이번에 만들 스킬 하나를 정한다. 전부 세팅하지 않는다 — 한 줄이 돌아야 둘째 줄이 보인다.

병목을 직접 묻지 않는다("어디가 병목입니까"는 답이 안 나온다). 대신 줄기 표의 **"내가 하는 것"** 칸을 같이 보며 "이 중에 시간이 제일 많이 드는 게 어느 줄이에요, 놓치면 제일 큰 게 어느 줄이에요"를 묻는다. 응답 핵심업무의 "신경점"에 적은 문장이 있으면 "여기 이렇게 적으셨는데 이 줄 얘기예요?"로 대본다. 본인이 고른 줄이 병목이고, 증상은 본인 말로 받아 적는다.

그 줄에 스킬 하나를 정한다 — 입력(어느 원본함의 무엇) → 출력(어느 파일에 무엇) 한 쌍. 이름은 본인이 붙인다. 그리고 "이 중에 꼭 본인이 봐야 하는 것"을 하나 묻는다 — 밖으로 나가는 것(메신저 전파·Jira 생성·문서 공유)은 답에 없어도 한 번 짚는다. 3절에 적고 `병목 [x]`.

## 4단계 — 깔기

목적: 확정된 배선도대로 실물을 만든다. 만드는 것은 넷이고, 넷 다 5절에 어디 만들었는지 적는다. `.claude/` 아래 쓰기는 권한 확인 창이 뜬다 — 만들기 전에 "확인 창이 뜨면 허용해 주세요"라고 먼저 말한다.

1. **줄기 폴더** — 줄기마다 하나. 번호는 세지 않는다, 스크립트가 센다:
   ```bash
   bash .claude/scripts/new_folder.sh 10-projects "<줄기 이름>" progress      # 끝이 있는 일
   bash .claude/scripts/new_folder.sh 20-operations "<줄기 이름>" progress    # 계속 도는 일
   ```
   끝이 있는지 계속 도는지는 본인에게 묻는다. 만들어진 `progress.md`(킷 템플릿 `00-system/01-templates/progress-template.md` 그대로)가 그 줄기의 **기록 파일**이다 — 두기가 타임라인 표에 쌓인다. 1절 표의 "기록 파일" 칸에 경로를 적는다.
2. **원본함** — 선언표의 들어오는 곳마다 `00-inbox/raw/<들어오는 곳>/` 폴더와 `README.md` 한 줄: 무엇이 쌓이고 어떻게 들어오나(MCP 도구 / CLI 명령 / 본인이 넣음). 원본은 고치지 않는다는 한 줄도. 2단계에서 이미 떨어진 파일은 그대로 둔다.
3. **내 수집 스킬** — `.claude/skills/<본인이 붙인 이름>/SKILL.md`. 이 PC에서 이 사람 것으로 만든다. 지시서 내용: 2절 선언표를 읽는다 → 줄마다 된 호출을 "언제부터 = 마지막 수집 때"로 반복한다(MCP 줄은 그 도구를 부르고, CLI 줄은 `scripts/<줄>.sh`에 명령을 넣어 돌리고, 직접 넣기 줄은 건너뛴다) → 원본함 규약대로 파일을 떨어뜨린다 → `수집-상태.md`를 갱신한다 → 마지막에 줄마다 `N건 / 0건 / 안 돌았다`를 찍는다. `allowed-tools`는 읽기·쓰기·Bash와 선언표에 적힌 MCP 도구만. 표면 경로는 주지 않는다 — 수집 스킬은 원본함까지만.
4. **병목 스킬** — `.claude/skills/<본인이 붙인 이름>/SKILL.md`. 3단계의 입력→출력 한 쌍만. 원칙 셋을 문장이 아니라 구조로 넣는다:
   - 금지는 도구로: `allowed-tools`를 그 일에 필요한 것만으로. 읽기만 하는 스킬에 Write를 주지 않는다.
   - 제안과 확정을 가른다: 출력은 원본 파일의 `## 제안` 절 또는 별도 제안 파일까지. 기록 파일(progress.md)·todo 경로를 스킬에 주지 않는다 — 옮기는 것은 본인이 확정한 뒤 `morning`이 한다.
   - 조용한 실패를 없앤다: 처리 건수가 0이면 "0건"과 "안 돌았다"를 구분해 찍는다. `check_lanes.sh`가 그 예다.

아침에 이 둘을 부르는 것은 킷의 `morning` 스킬이다 — 사람마다 다르지 않아서 미리 들어 있다. 5절에 수집 스킬 이름을 적어야 `morning`이 찾는다. `깔기 [x]`.

## 5단계 — 한 바퀴

목적: 모은다 → 제안 → 승인 → 둔다가 실제 자료로 도는지 본다. 자료 하나로는 안 된다 — **최소 세 건, 줄기가 둘 이상 섞이게.** 오늘 실제로 받은 것이어야 한다. 만든 예시는 안 된다.

1. 본인이 실제 자료를 넣는다. MCP·CLI 길이면 수집 스킬이 끌어오고, 직접 넣기면 본인이 원본함에 넣는다.
2. 건마다 원본 파일 안 `## 제안`에 셋을 적는다 — 줄기(섞이는 통로의 건만 판단, 아니면 통로가 정한다. 못 정하면 `불명`) · 반영할 내용 한 줄 · 근거 한 줄. 원본 본문은 안 건드린다.
3. 본인이 건마다 확정하거나 고친다. `불명`이 나오면 그 자리에서 1절 표를 고친다 — 이것이 이 단계의 소득이다.
4. 확정된 것만 둔다 — 그 줄기의 기록 파일(progress.md)에 한 줄, 할 일이면 `todo` 스킬, 일정이면 캘린더에 넣을지 묻는다. 기록 파일을 고쳤으면 `ripple`을 부른다. 6절 표의 마지막 칸에 돌렸는지 적는다.
5. 6절 표에 건마다 한 줄. `한바퀴 [x]`.

7절에 첫 돌아보기 날짜만 받아 적고 끝낸다. "다 됐다"가 아니라 **"흐름은 돈다, 다음은 첫 돌아보기에 본다"**가 이 스킬의 끝 문장이다. 직접 넣기로 둔 길이 있으면 그날 무엇부터 바꿀지 한 줄 같이.

## 하지 않는 것

- 응답에 없는 줄기·칸을 지어 채우는 것. 초안이 지어낸 것이면 본인은 고치기만 하게 되고, 그건 본인 배선도가 아니다.
- 여러 줄기에 스킬 여럿. 하나가 돌아야 둘째가 보인다.
