# YAML 선언과 실행 약속

Claude Code의 wiring·morning·개인 수집 스킬이 함께 읽는 규약이다. 참가자는 업무를 말하고 승인하며, Claude가 YAML을 작성한다.

## 준비

Python 3.9 이상만 있으면 된다. **패키지 설치는 없다** — YAML 읽기는 `scripts/_vendor/`에 동봉한 PyYAML 순수 파이썬 부분(MIT)을 쓰고, 시스템에 PyYAML이 있으면 그것을 먼저 쓴다. 파이썬 확인은 setup-workspace 4단계가 원본이다.

스크립트는 항상 래퍼로 부른다. 래퍼가 실제로 도는 파이썬을 고른다(윈도우의 `python3`는 Store 가짜라 `python3 …`로 직접 부르지 않는다).

```bash
bash .claude/skills/wiring/scripts/wiring.sh validate
```

파이썬이 없으면 래퍼가 `오류: 실행되는 파이썬 3이 없습니다`로 멈춘다. 그때는 검사가 안 된 상태라고 말하고 멈춘다. 마크다운으로 몰래 돌아가지 않는다.

## 원본 셋

- `00-system/wiring/선언.yaml`: 주인·진행·줄기·통로·수집스킬·병목·돌아보기. 사람이 확정한 설정이다.
- `00-system/wiring/실행상태.yaml`: 스크립트가 관리하는 수집 결과와 자료별 상태. 손으로 고치지 않는다.
- 원본함의 파일: 가져온 본문 그대로. 제안은 별도 `00-system/wiring/제안/<자료id>.md`에 둔다.

`배선도.md`는 `render`로 만드는 보기용 파일이다. 설정은 반드시 YAML에서 고치고 다시 만든다. 설정과 상태에 인증값을 넣지 않는다. 호출에 인증이 필요하면 환경변수·기존 MCP 설정을 사용한다.

## 선언 필드

시작은 `assets/declaration-template.yaml`을 복사한다. 확인되지 않은 값은 빈칸이며, 해당 단계가 끝나기 전에 채운다. `진행`은 앞에서부터 true가 된다.

- `주인`: CLAUDE.md 프로필의 이름. 비어 있으면 본인에게 묻는다(검사가 `주인 누락`으로 막는다).
- `줄기[].id`·`통로[].id`: 영어 소문자와 숫자·밑줄·하이픈의 고정 식별자. 이름을 바꿔도 id를 바꾸지 않는다.
- `줄기[].통로`: 들어오는 통로 id 목록. `기록`은 `10-projects/` 또는 `20-operations/` 아래 실제 progress.md 상대 경로.
- `통로[].섞임`: 여러 줄기가 오거나 외부 접점이면 true.
- `길`: MCP / CLI / 직접 넣기. `원본함`: 00-inbox/raw 아래 통로별 폴더.
- `범위`: 채널·탭·필터·처음 수집할 기간과 이후 이어받기 방법. `고유키`: 메시지 id, 문서 id+수정버전 등 원천의 식별 규칙. 같은 문서의 수정본은 버전이 다른 자료로 보존한다.
- `호출`: MCP는 `{도구: mcp__<서버>__<도구>, 인자: {실제키: 실제값}}`, CLI는 `{argv: [실행파일, 인자1, 인자2]}`. 실제로 성공한 호출을 적고 자리표시자를 남기지 않는다. 검사는 명령을 실행하지 않지만, CLI 실행파일이 이 PC에 있는지·MCP 서버가 `.mcp.json`에 있는지(파일이 있을 때)·자리표시자(`<…>`·`{{`·`YOUR_`·`...`)는 본다.
- `근거`: 그 호출로 실제 가져온 원본 경로. 직접 넣기는 호출·근거가 비어 있어도 된다.
- `수집스킬`·`병목.스킬`: `.claude/skills/<이름>/SKILL.md`의 이름. 서로 다른 스킬이어야 한다. `병목.실행`: 아침 / 직접. 아침이면 morning이 수집 뒤 호출한다. 직접이면 본인이 부르는 말을 스킬 description에 적는다.
- `병목.통로`: 병목 스킬이 받을 자료의 통로 id 목록(병목 줄기의 통로 중에서). morning은 이 목록으로 대상 자료를 고른다 — `queue`가 자료마다 `병목대상: true/false`로 찍는다. `입력`·`출력`은 사람이 읽는 설명이다.
- `병목.승인기준`: 사람이 확인할 내용. 도구 권한 제한만으로 승인 절차가 보장된다고 말하지 않는다.

## 실행 명령

대상 워크스페이스 루트에서 실행한다. 종료 코드 0은 해당 기계 검사 통과, 1은 오류다. 실제 사내 도구 호출·판단의 정확성·승인 진위는 이 검사로 판정할 수 없다.

```bash
bash .claude/skills/wiring/scripts/wiring.sh validate
bash .claude/skills/wiring/scripts/wiring.sh render
# morning 시작 전: 깔기 완료·기록 파일·스킬·근거가 실재해야 함
bash .claude/skills/wiring/scripts/wiring.sh validate --ready
```

`validate` 결과에는 `미등록원문`(원본함·drop 폴더에 있는데 등록 안 된 파일)과 `원본없음`(등록됐는데 원본 파일이 지워진 자료 id)이 같이 나온다. 둘 다 오류는 아니지만 본인에게 보여준다 — 미등록은 `intake`로, 원본없음은 그 자료를 버림으로 닫거나 원본을 되돌린다.

### MCP·CLI 자료 등록

수집한 텍스트를 임시 파일에 보존한 뒤 다음 명령으로 원본함에 넣는다. 인자의 통로 id와 고유키는 선언과 원천에서 가져온 실제값이다. 명령의 사용자 문자열은 셸 인용을 한다.

```bash
bash .claude/skills/wiring/scripts/wiring.sh store input '원천의-고유키' /임시/원문.md
```

반환값 `신규등록: true`인 자료만 신규 건수로 센다. 같은 통로·고유키·본문이면 `신규등록: false`와 같은 자료 id를 반환하고 기존 상태를 유지한다. 같은 키인데 내용이 다르면 실패한다. 원문을 덮어쓰거나 키를 임의로 바꿔 넘기지 말고 원천 수정버전을 확인한다. 원문 날짜·출처는 본문 또는 임시 파일에 함께 보존한다. 같은 고유키를 재수집할 때 가져온 시각·임시 경로처럼 매번 달라지는 값을 원문에 붙이지 않는다. 이런 실행 정보는 실행상태에 둔다. 원본함 파일에 제안·상태를 덧붙이지 않는다. 원문은 UTF-8이어야 한다(아니면 검사가 안내 문구로 거부한다).

### 직접 넣기 자료 등록

본인은 파일을 `00-inbox/drop/<통로id>/`에 둔다(파일 이름이 고유키가 된다). 수집 스킬은 통로마다 다음 한 줄을 부른다.

```bash
bash .claude/skills/wiring/scripts/wiring.sh intake input
```

`intake`는 drop 폴더와 원본함의 미등록 파일을 등록하고, 본문이 원본함에 그대로 들어간 것을 확인한 뒤 원래 파일을 지운다(원문은 `<원본함>/<자료id>.md`에 남는다). 결과 `등록`(신규)·`이미등록`·`실패`를 그대로 보고하고 수집 결과(`result`)도 같이 남긴다. 한 파일이 실패하면 거기서 멈추고 그 파일은 지우지 않는다.

### 수집 결과

통로의 조회 범위 전체를 가져와 등록한 뒤에만 성공을 기록한다. 페이지가 남았거나 일부 저장이 실패하면 실패로 기록한다. `cursor`는 이번 조회에서 처리 완료한 끝 지점이지 실행이 끝난 시각이 아니다. 다음 조회는 실행상태의 `이어받기`를 사용한다. 경계 자료를 겹쳐 받아도 store가 중복을 가른다.

```bash
bash .claude/skills/wiring/scripts/wiring.sh result input --ok --cursor '원천의-완료지점' --count 3
bash .claude/skills/wiring/scripts/wiring.sh result input --error '수집 실패 원문'
```

실패는 마지막 성공 지점을 바꾸지 않는다. 0건 성공은 `--ok --count 0`으로 남긴다. 오류 문자열의 `token`·`key`·`bearer` 같은 낱말 뒤는 스크립트가 가려서 저장하지만, 인증값이 든 에러는 넘기기 전에 먼저 지운다.

## 승인과 재개

```bash
bash .claude/skills/wiring/scripts/wiring.sh queue
bash .claude/skills/wiring/scripts/wiring.sh status 자료id 승인대기 --proof '제안/자료id.md'
# 실제 사용자 답을 받은 뒤에만:
bash .claude/skills/wiring/scripts/wiring.sh status 자료id 승인됨 --proof '사용자 승인 원문과 일시'
# 파일 반영을 확인한 뒤에만:
bash .claude/skills/wiring/scripts/wiring.sh status 자료id 반영완료 --proof '반영 파일과 항목'
```

`queue`는 신규·승인대기·승인됨을 모두 반환한다. 신규만 제안을 새로 만들고, 승인대기는 기존 제안을 다시 보여주며, 승인됨은 중단된 반영부터 잇는다. 버림도 사용자 확정 후 `status 자료id 버림 --proof ...`으로 남긴다. CLI에 근거를 넣는 것은 승인 증명이 아니다. Claude는 실제 대화의 승인을 확인해야 한다.

스크립트가 막는 것 둘: `승인대기`는 `00-system/wiring/제안/<자료id>.md`가 있어야 하고, `반영완료`는 `<!-- wiring:자료id:항목번호 -->` 표식이 기록 파일·할 일·노트 어딘가에 있어야 한다(`00-system/`·`00-inbox/`·`.claude/` 안의 언급은 반영으로 치지 않는다).

반영할 각 항목에 그 표식을 둔다. 재개 시 대상 파일의 같은 표식을 찾고 이미 있으면 또 추가하지 않는다. 한 원문에 줄기·할 일이 여럿이면 제안에서 항목을 나누고 각각의 반영 위치를 남긴다. 일부만 승인되면 자료는 승인대기로 두고 승인된 항목만 반영한다 — 어느 항목이 반영됐는지는 제안 파일에 적는다. 모든 승인 항목의 반영이 확인된 뒤 자료를 반영완료로 바꾼다. 파일 쓰기와 상태 갱신 사이에 멈춰도 이 표식으로 다시 확인한다. 외부 캘린더는 별도 승인과 생성 결과 조회로 중복을 확인하며, 확인할 수 없으면 자동 재전송하지 않는다.

### 병목 스킬과 morning의 연결

- morning은 `queue`에서 `병목대상: true`이고 `상태: 신규`인 자료 id들을 공백으로 이어 Skill 도구의 인자로 넘긴다.
- 병목 스킬은 자료 id마다 원본(실행상태의 `원본`)을 읽고 `00-system/wiring/제안/<자료id>.md` **만** 쓴다. status를 부르지 않고, 기록 파일·할 일·캘린더를 바꾸지 않는다.
- morning이 제안 파일이 생겼는지 확인한 뒤 `status 승인대기`를 부른다. 병목 스킬이 실패한 자료는 신규로 남긴다.

동시에 두 세션에서 수집·반영하지 않는다. 이 버전의 실행상태는 단일 Claude Code 세션용이며 동시 쓰기 잠금은 제공하지 않는다.

## 기존 마크다운 배선도에서 이어가기

기존 `배선도.md`(머리말에 `진행:` 줄이 있는 옛 형식)가 있고 `선언.yaml`이 없으면: 옛 파일을 `배선도-이전.md`로 이름을 바꾸고, 그 1절 줄기 표를 1단계의 **첫 판**으로 화면에 보여준 뒤 본인에게 다시 확정받는다. 옛 파일의 `진행:` 체크를 완료로 옮기지 않는다 — 2단계 이후는 새 규약(store·근거·병목.통로)으로 다시 확인한다. 옛 `수집-상태.md`와 원본함의 옛 파일(`## 제안` 절이 붙은 것)은 그대로 두고 등록하지 않는다. 그 안의 제안이 반영됐는지는 본인에게 말로 확인한다.

## 검사 범위

`validate`가 잡는 것: 중복 YAML 키·id 형식·통로 참조·워크스페이스 밖 경로·진행 순서·길 값·호출 형식·자리표시자·CLI 실행파일 유무·MCP 접두와 서버(`.mcp.json`이 있을 때)·근거 파일·기록 파일 위치·원본함 폴더·스킬 파일·같은 스킬 중복·병목 통로·돌아보기.
`status`가 잡는 것: 상태 건너뛰기·근거 없는 전이·제안 파일 없는 승인대기·표식 없는 반영완료.
`store`·`intake`가 잡는 것: 빈 원문·UTF-8 아님·같은 키의 다른 본문.

못 잡는 것: 호출이 실제로 도는지(명령을 실행하지 않는다), 사용자 공통(user scope)으로만 등록한 MCP 서버, 제안·반영 내용의 업무적 정확성, 승인의 진위, 두 세션 동시 쓰기. 이것은 대화와 사람이 본다.

시험은 `bash .claude/skills/wiring/scripts/wiring.sh` 대신 `python3 .claude/skills/wiring/scripts/test_wiring.py`로 돌린다. 각 시험은 통과시키면 안 되는 사례를 하나씩 심어 두었다.
