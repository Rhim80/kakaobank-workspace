# Wiki Schema

> "The knowledge is compiled once and then kept current, not re-derived on every query." — Karpathy
> 이 파일은 AI와 함께 co-evolve 한다. 위키 운영 중 발견된 패턴은 여기에 반영.

## 구조

```
00-wiki/
├── SCHEMA.md         # 이 파일 (CLAUDE.md에서 @import, AI와 co-evolve)
├── index.md          # 전체 토픽 카탈로그 (카테고리별, 메타데이터 포함)
├── log.md            # 시간순 활동 기록 (append-only, parseable)
├── README.md         # 운영 가이드
└── [토픽].md          # 토픽 페이지 (flat, 케밥케이스 한글 또는 영어)
```

## 3계층

| 계층 | 위치 | 역할 | 누가 관리 |
|------|------|------|----------|
| Raw Sources | 10-projects/, 41-daily/, 00-inbox/ 등 | 원본 소스. **불변** — 읽기만, 수정 안 함 | 사용자 |
| Wiki | **00-wiki/** | 소스에서 추출한 지식이 통합되어 복리로 축적 | AI가 쓰고, 사용자가 읽고 승인 |
| Schema | **이 파일** + wiki-ingest/wiki-lint 스킬 | 위키 운영 규칙. AI와 co-evolve | 사용자 + AI |

## 3오퍼레이션

### Ingest (소스 → 위키 통합)
- **트리거**: 수동 호출 ("wiki-ingest"), 또는 다른 스킬에서 자동 호출
- **핵심**: 소스를 읽고 → 기존 페이지에 통합 → 핵심 갱신 → 교차 참조 강화 → 모순 감지
- **supervised mode**: 한 소스씩 처리, 사용자와 핵심 포인트 논의 후 반영 (기본)
- **batch mode**: 여러 소스 일괄 처리 (감독 최소화)

### Query (위키 검색 → 답변)
- **구현**: wiki-query 스킬 (index.md 확인 → Grep → Read → 인용과 함께 답)
- **트리거**: 주제·개념·방법·과거 판단을 물으면 **답하기 전에 00-wiki를 먼저 확인**
- **핵심**: 답변 결과가 가치 있으면 **다시 위키에 저장**(쓰기는 wiki-ingest가 한다). 대화에서 나온 분석/비교가 위키에 남음
- **위키는 원본이 아니다**: 방향·판단은 위키를 그대로 써도 되지만, **금액·날짜·이름 같은 사실값은 그 근거의 `[source: …]` 원본 파일까지 열어** 확인한다

### Lint (위키 헬스체크)
- **트리거**: 수동 호출 ("wiki-lint", "위키 점검")
- **점검 항목**: 여기 나열하지 않는다 — 원본은 wiki-lint 스킬의 Step 2 목록이다. 여기 복제하면 항목이 늘 때 조용히 낡는다

## 복리의 메커니즘

단순 축적(파일 수 증가)이 아닌 **통합(integration)**:

1. **근거 추가** — 새 소스의 증거가 기존 페이지에 쌓임
2. **핵심 갱신** — 새 근거가 기존 이해를 바꾸면 핵심 요약이 더 정교해짐
3. **교차 참조 강화** — 같은 소스에서 여러 토픽이 enriched → 서로의 Related 연결
4. **모순 감지와 종결** — 새 내용이 기존 주장과 상충 → `[!contradiction YYYY-MM-DD]` 플래그 → 판정되면 `[!superseded YYYY-MM-DD → 이긴 근거]`로 닫음 (아래 「모순의 수명주기」)
5. **Open Questions 해소** — 기존 질문이 새 소스로 답변되면 갱신
6. **Query 환류** — 대화에서 나온 분석/비교가 새 synthesis 페이지로 저장

## 모순의 수명주기

플래그를 다는 규칙만 있고 떼는 규칙이 없으면 열린 채 쌓인다. 그래서 여는 법과 닫는 법을 함께 정한다.

- **열기**: `[!contradiction YYYY-MM-DD]` — **날짜를 플래그 안에** 넣는다. 밖에 쓰거나 `[source: …]`에만 두면 나이를 못 센다
- **닫기**: 판정되면 지우지 않고 `[!superseded YYYY-MM-DD → 이긴 근거 한 줄]`로 바꾼다. 진 쪽 본문은 그대로 남긴다 — 왜 그렇게 정했는지가 남아야 같은 논쟁이 다시 열리지 않는다
- **판정자는 사용자다.** ingest도 lint도 스스로 닫지 않는다. lint는 30일 넘게 열린 것을 모아 보여주기만 한다(D-2)
- **`[!contradiction …]` 꼴은 플래그 자체에만 쓴다** — 다른 데서 그것을 가리킬 때는 "모순 표시"처럼 다른 말로 쓴다. 참조가 같은 꼴이면 기계가 실제 플래그와 못 가른다

## 페이지 유형

| 유형 | 설명 | 예시 |
|------|------|------|
| **concept** | 개념, 원칙, 아이디어 | 동사-중심-사고.md |
| **entity** | 특정 대상 (조직, 프로젝트, 도구) | Claude-Code.md |
| **synthesis** | 여러 소스의 비교/분석 | AI-도구-비교.md |

**유형은 분류만이 아니라 "얼마나 오래 안 건드려도 괜찮은가"를 정한다** — 가치·개념은 반년을 묵어도 정상이고 조직·도구 페이지는 두 달이면 낡는다. 기한과 세는 법은 wiki-lint의 C 항목이 원본이다(여기 복제하지 않는다).

## 토픽 페이지 형식

```markdown
# [토픽명]

> **관련**: [[토픽A]] · [[토픽B]] · [[토픽C]]
> **Facets**: 키워드1 · 키워드2 · 키워드3

## 핵심 (현재 아는 것의 요약)
## 근거 (소스별 증거, 아래 「출처와 중복」 형식으로 인용)
## 적용 (내 맥락에서 실제 사용)
## Open Questions (아직 모르는 것)
## Related (다른 토픽 링크)
---
Sources: [소스 목록]
Last enriched: [날짜]
```

## 운영 규칙

- **기존 페이지 확장 우선**: 비슷한 토픽 있으면 새 파일 만들지 않음
- **source 인용 필수**: 모든 추가에 출처와 날짜
- **모순은 삭제하지 않음**: 열 때 `[!contradiction 날짜]`, 닫을 때 `[!superseded 날짜 → 이긴 근거]`. 판단은 사용자 (「모순의 수명주기」)
- **Query 환류**: 대화에서 나온 가치 있는 분석/비교는 synthesis 페이지로 저장
- **파일명**: 케밥케이스 (한글 또는 영어)
- **Co-evolution**: 이 SCHEMA 자체도 위키 운영 중 발견된 패턴을 반영하여 갱신

## Infobox와 index

관련 줄은 최대 6개 토픽 링크를 둔다. Facets는 `·`로 구분한 키워드이며 85자 권장 상한이다. index 설명이 완전한 문장이면 Facets를 생략해도 된다. index는 토픽·유형·한 줄 설명·enriched의 4열이며 설명은 완전한 문장 1개, 70자 이내다. 허브는 다른 토픽의 관련 줄에서 참조된 횟수 상위 5개다.

## 출처와 중복

새 근거는 `[source: 워크스페이스 상대경로 또는 완전한 https:// URL, YYYY-MM-DD, §소제목 또는 인용: 짧은 원문]`으로 남긴다. 날짜는 원본 날짜이며 알 수 없으면 `날짜 미확인`으로 표시한다. 웹 조사일이 원본 날짜와 다르면 따로 적는다. 저장된 대화 원문이 없으면 `[source: 대화 원문 미보존: 주제, YYYY-MM-DD, 인용: 현재 대화의 짧은 문장]`으로 표시한다. 보존 파일이 있다고 지어내지 않는다.

같은 출처의 같은 주장·같은 근거를 재입력하면 추가하지 않는다. 출처가 같아도 새로운 근거·반례면 통합한다. 기계는 동일 불릿을 찾을 뿐이고 의미 중복은 원문과 기존 근거 대조로 판단한다. 과거 표기의 경로를 보정할 때도 후보가 유일하고 내용이 맞는 것을 읽어 확인한 경우만 바꾼다. 복수 후보·접근 불가·제목만 있는 출처는 미확인으로 남긴다.

## 갱신일

`Last enriched`는 마지막 지식 보강일이다. 근거·핵심·새 적용 지식의 보강에만 갱신한다. 링크 수선·표기 통일·정렬·운영 설명 정정은 날짜를 올리지 않는다. footer 첫 날짜만 현재값이며 `| 이전:` 뒤는 이력이다. 본문·log·Git diff가 갈리면 비교해 판정하고, 판별 불가면 `미확인`으로 남긴다.

index의 enriched는 본문 날짜와 같아야 한다. sources 열은 쓰지 않는다. `wiki_check.py --index`는 본문 날짜에서 후보를 만들며 토픽·유형·설명·카테고리를 보존한다. 날짜 자체의 진실성은 원문·이력 대조가 필요하다. 출력은 검토 후 반영하고 입력 index로 직접 리다이렉트해 덮어쓰지 않는다.

## log.md 규칙

활동은 파일 맨 아래에 추가한다. `## [YYYY-MM-DD] ingest | 소스명`, `query | 질문`, `lint | Wiki Health Check` 형식을 쓴다. 원본 경로·변경 토픽·핵심 변화·모순·검사 명령과 결과를 기록한다. 중복 생략만 한 경우 그 사실을 적고 지식 보강일은 바꾸지 않는다. 과거 기록은 보존한다. index에는 활동 이력을 쌓지 않는다. index 내용이 바뀌면 footer의 Last updated만 작업일로 갱신하고, 토픽의 지식 보강일과 구분한다.

## 기계 검사 기준

실행 방법은 `.claude/skills/wiki-lint/SKILL.md`의 「기계 검사 실행」을 따른다. 검사기는 읽기 전용이며 표준 라이브러리만 사용한다. `--files`는 변경 토픽과 그 index 항목, 기본은 전체 토픽을 검사한다. `--index`는 본문 날짜를 반영하고 옛 sources 열을 제외한 후보를 stdout으로만 출력한다. 옛 5열 index도 검사에서 허용하되 새로 만들지 않는다.

- 오류: index 등록/대상·유형, H1/필수 절/관련 줄, 깨진 링크, 날짜 형식/불일치/미래 날짜, 관련 링크 상한, 모순 날짜.
- 주의: 출처 경로·날짜·소제목/인용 부족, 동일 근거 불릿, 설명/Facets 길이, 근거 크기, 노후·열린 모순. 주의는 내용의 참·거짓 판정이 아니다.
- 노후: concept 180일, entity 60일, synthesis 120일 초과. 열린 모순은 30일 초과를 구분한다.
- 근거 크기: `## 근거`부터 다음 H2 전까지 최상위 `- ` 항목만 센다. 30 초과는 정리 고려, 50 초과는 분리안 후보다. 자동 삭제·분리는 하지 않는다.
- 코드펜스·인라인 코드·HTML 주석 속 예시와 Sources/Last enriched 기록은 현재 링크·모순에서 제외한다. 링크는 워크스페이스 파일·폴더의 이름/경로 꼬리·상대경로를 인정한다.
- `Origin: root`를 명시한 기존 페이지는 절 구조를 보존한다. H1·관련 줄·등록·날짜·출처·링크는 동일하게 검사한다. 특정 토픽 이름으로 예외를 주지 않는다.
- 원문과 주장의 일치, 의미 중복, 허브·역방향 연결, log 내용과 실제 변경의 일치는 사람이 원문·변경 전후를 대조한다. 기계 검사 통과만으로 이를 완료했다고 말하지 않는다.
